# depth_capture — сбор полной глубины рынка для shopalbi

Публичный API AODP отдаёт только **лучшую** цену покупки и продажи по каждому
городу/качеству. Сколько лотов и по каким ценам реально стоит в ордербуке — он
не отдаёт. Этот агент закрывает пробел: он **пассивно читает сетевой трафик
твоего же клиента Albion**, разбирает ответы рынка, которые сервер и так шлёт
твоему клиенту при открытии рынка, и отправляет **полные ордербуки** (каждый
уровень цены с количеством) в бэкенд shopalbi.

Это тот же приём, на котором построен весь экосистемный сбор данных Albion,
включая официальный клиент AODP: только чтение, без отправки, инъекций или
модификации пакетов. Разработчики Albion такое чтение рыночного трафика
разрешают (см. README проекта).

## Что делает

```
UDP/5056 (Photon)  →  разбор Photon (Protocol16)  →  поиск рыночных ответов
                                                          ↓
                                    нормализация ордеров (цена /10000, @чар, город)
                                                          ↓
                                 группировка в ордербуки  →  POST /api/ingest/orders
```

Рыночные ответы находятся **структурно** — по наличию полей ордера
(`UnitPriceSilver`, `Amount`, `AuctionType`) в JSON внутри параметров, а не по
номеру операции. Поэтому агент переживает патчи клиента без правок кода.

## Требования

- Python 3.10+
- **Windows:** установленный [Npcap](https://npcap.com/), запуск терминала
  «от имени администратора».
- **Linux/macOS:** libpcap (обычно уже есть), запуск через `sudo`.

```bash
cd tools/depth_capture
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка на бэкенде (один раз)

Ингест закрыт по умолчанию (fail-closed). Задай общий секрет на сервере
shopalbi и включи приём:

```bash
# в .env или docker-compose.yml бэкенда
SHOPALBI_INGEST_TOKEN=<длинная_случайная_строка>
```

Перезапусти бэкенд. Проверить: `GET /api/depth/status` → `"ingest_enabled": true`.

## Запуск агента

Агент запускается **на машине, где играешь** (или которая видит игровой трафик).

```bash
# Windows (Администратор):
set SHOPALBI_INGEST_TOKEN=тот_же_секрет
python -m depth_capture --backend http://АДРЕС_VPS:8000

# Linux/macOS:
sudo SHOPALBI_INGEST_TOKEN=тот_же_секрет python -m depth_capture --backend http://АДРЕС_VPS:8000
```

Дальше просто **открывай рынки в игре** — в городах и на Чёрном рынке. Каждый
раз, когда ты открываешь вкладку рынка, клиент получает ордербук, а агент его
перехватывает и отправляет. Логи раз в 30 секунд показывают счётчики.

Полезные флаги:

| Флаг | Смысл |
|---|---|
| `--backend URL` | адрес shopalbi (или env `SHOPALBI_BACKEND_URL`) |
| `--token СЕКРЕТ` | ингест-токен (или env `SHOPALBI_INGEST_TOKEN`) |
| `--iface ИМЯ` | сетевой интерфейс (если несколько NIC) |
| `--pcap ФАЙЛ` | воспроизвести .pcap/.pcapng вместо живого захвата |
| `--port N` | UDP-порт Photon (по умолчанию 5056) |
| `--list-ifaces` | показать доступные интерфейсы |
| `--log-level debug` | подробный лог, включая каждый пойманный ордербук |

## Калибровка городов (важно)

Рыночные ордера содержат числовой `LocationId`. Соответствие
`LocationId → город` задано в [`locations.py`](locations.py) значениями,
которыми пользуется публичная тулза AODP. Если после старта какой-то город в
логах отображается как `loc_<число>`, значит id сместился на текущем патче —
добавь его в файл-override и перезапусти:

```bash
# locations.json
{ "3005": "Caerleon", "1002": "Lymhurst", "3003": "Black Market" }
```

```bash
SHOPALBI_CAPTURE_LOCATIONS=/путь/locations.json python -m depth_capture ...
```

Сырой `LocationId` всё равно сохраняется (как `loc_<id>`), так что данные не
теряются — их можно переразметить позже.

## Проверка без игры

```bash
python -m depth_capture.selftest      # синтетический пакет → парсер → ордербуки
```

## Что появляется в shopalbi

- `GET /api/depth?item_id=T5_BAG@1&city=Caerleon&quality=2&type=offer` —
  полный ордербук: уровни цен, количество, накопительная глубина.
- `GET /api/depth/flip?item_id=T5_BAG@1&quality=2` — сколько лотов реально
  вывозится в плюс из каждого города на ЧР, со средней ценой покупки/продажи и
  маржой последнего лота (честный потолок вместо одной min/max точки).
- `GET /api/depth/status` — сколько ордербуков и насколько они свежие.

## Приватность и безопасность

- Агент **только читает**. Он не открывает сокеты в игру, ничего не пишет в
  игровой трафик и не трогает клиент.
- Наружу он шлёт только рыночные данные (id предмета, город, качество, цена,
  количество) на **твой** бэкенд по токену. Никаких учёток, чата, координат.
