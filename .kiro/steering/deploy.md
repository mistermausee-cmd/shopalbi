# Обновление на VPS — включать в каждый ответ

Если в этой сессии что-то менялось в коде и было запушено, **ответ обязан
заканчиваться готовой командой обновления**. Одной строкой, чтобы скопировать и
вставить.

## Окружение

Ubuntu 24.04 на Azure, 4 vCPU / 16 ГБ. Работа под `root`, репозиторий в
`~/shopalbi`, Docker Compose, порт 8000. Логи на хосте в `/root/logs`.

## Команда (пока PR не смержен — берём ветку)

```bash
cd ~/shopalbi && \
git fetch --all --prune && \
git checkout -B v5 origin/feat/v5-audit-and-rebuild && \
sudo docker compose up -d --build && \
echo '--- ждём старт ---' && sleep 30 && \
curl -s localhost:8000/api/health && echo && \
sudo tail -n 25 /root/logs/shopalbi.log
```

## Команда после мержа в main

```bash
cd ~/shopalbi && \
git fetch --all --prune && \
git checkout -B main origin/main && \
sudo docker compose up -d --build && \
echo '--- ждём старт ---' && sleep 30 && \
curl -s localhost:8000/api/health
```

## Обязательные части команды и почему

1. **`git fetch` + `git checkout -B <ветка> origin/<ветка>`, а НЕ `git pull`.**
   Уже был случай: рабочее дерево стояло на ветке фичи, `git pull` ответил
   «Already up to date», `docker build` вышел полностью `CACHED`, старый
   фронтенд продолжил работать — и это выглядело как вечная загрузка. `git pull`
   в инструкциях для этого проекта не использовать.

2. **Проверка версии в конце.** По внешнему виду сайта нельзя понять, поднялся
   ли новый код. Всегда добавлять `curl -s localhost:8000/api/health` и писать в
   ответе, какую версию там ожидать, плюс явно: «если версия другая — код не
   поднялся».

3. **Не предлагать `docker compose down`/`stop`.** `up -d --build` сам
   пересоздаёт контейнер. Останавливать вручную не нужно, и это стоит сказать,
   потому что вопрос задавался.

## Что ещё упоминать рядом с командой

- Данные лежат в named volume `shopalbi-data` и переживают обновление; миграции
  схемы применяются на старте автоматически.
- Если ожидается заметная пауза после перезапуска (например длинный первый
  рефреш истории) — предупредить и назвать время.
- Логи: `sudo docker compose logs -f` или файл `/root/logs/shopalbi.log`.
