# shopalbi — анализатор Чёрного рынка Albion Online

Веб-инструмент для схемы **«купил в королевском городе → отвёз в Карлеон →
продал на Чёрный рынок»**. Сервер **Europe**, аккаунт с **Premium**.

Собирает цены со всех королевских городов и ЧР, считает средние цены и оборот за
день / 3 дня / неделю / месяц и выдаёт ранжированный список того, что реально
стоит везти — с прибылью в серебре и процентах, поправкой на риск ганка, оценкой
надёжности и **реальным количеством, которое физически есть на рынке**.

Игру запускать не нужно. Данные — публичный
[Albion Online Data Project](https://www.albion-online-data.com): REST для цен и
истории плюс живой NATS-поток рыночных ордеров (цена **и количество**).

## Вкладки

| Вкладка | Что даёт |
|---|---|
| 🔥 **Выгодные флипы** | Топ вещей на вывоз: где купить, за сколько выкупит ЧР, прибыль, прибыль с учётом риска, при каком % ганков сделка выходит в ноль, доступное количество, надёжность. |
| 🧮 **План закупки** | Вписываешь бюджет — получаешь город, список вещей и **сколько штук брать**. Количества ограничены реальными ордерами (и предложением города, и спросом ЧР), поэтому «купи 300 шт T4» больше не бывает. |
| 🏙 **Города закупки** | Где выгоднее базироваться по совокупности факторов. Карлеон учитывается отдельно: цены выше, но риск потерять груз нулевой. |
| 📊 **Средние цены** | Средневзвешенные по объёму цены и оборот по всем городам за период, самый дешёвый город, исторический спред к ЧР. |
| 🎒 **Мои сеты** | Вписываешь предметы, с которыми бегаешь — оружие, броню, маунта, зелья, еду, удочку — и получаешь город, где можно купить **всё сразу** дешевле всего. |

### Комбинированный отбор

Кнопка «⚖ Отбор» на вкладке флипов. Кликаешь по заголовкам столбцов — они
складываются в общий отбор, повторный клик по тому же столбцу его снимает.
Доступно 13 показателей: прибыль, %, с учётом риска, оборот ЧР, доступное
количество, скорость выкупа, цена закупки и другие.

Для каждого показателя считается **процентиль среди всех подходящих позиций**, а
не доля от максимума: распределения крайне перекошены (одна позиция с прибылью
500k рядом с тысячами по 2k), и нормировка по максимуму схлопнула бы всё
остальное в ноль. Итоговый балл — среднее процентилей, 100 означает «лучший по
всем выбранным показателям одновременно».

Зачем это нужно, на живых данных: сортировка только по `%` выводит наверх шлем с
маржой 232%, но оборотом 22 шт/день — его придётся продавать неделю.
Совокупный отбор по `% + оборот + скорость выкупа` даёт позиции с маржой 90–225%
**и** оборотом 2000+ шт/день.

### Мои сеты

Каталог для сетов намного шире основного (8 114 предметов против 6 402): в него
входят маунты, зелья, еда, инструменты и снаряжение собирателя, которые Чёрный
рынок не покупает вообще. Цены **не** подтягиваются для всего каталога — только
для предметов конкретного сета, поэтому фича стоит один-два запроса к API
независимо от размера каталога.

Города, где есть **все** позиции, ранжируются первыми: город дешевле, но без
одной вещи означает вторую поездку. Рядом показано, сколько вышло бы при закупке
по разным городам — то есть честная цена удобства одной поездки. Если нужного
качества нет в продаже, подставляется лучшее (помечается «замена») — это
переключается.

#### Эквивалент по силе предмета

Сила предмета в Albion считается так (проверено по
[вики](https://wiki.albiononline.com/wiki/Enchantment) — «каждый уровень
зачарования даёт +100 IP» — и по таблицам тиров на страницах экипировки, где
T2=500, T3=600, T4=700):

```
сила = 300 + (тир + зачарование) × 100
```

Значит одинаковую силу имеют:

```
T8.0  =  T7.1  =  T6.2  =  T5.3  =  T4.4   →  1100 IP
T7.0  =  T6.1  =  T5.2  =  T4.3            →  1000 IP
```

Для персонажа это одно и то же, а цены различаются заметно. При включённом
эквиваленте для каждой позиции подбирается самый дешёвый равносильный вариант,
**доступный в этом же городе** — потому что летать за каждой частью сета в разные
города смысла нет.

Замер на живом сете T8 (плита + плащ + сумка + оружие): без эквивалента
1 341 708 в Бресилиане, с эквивалентом — **1 135 701 там же (−15%)**, и городов
с полным комплектом стало 6 вместо 5.

**Именные артефакты не подменяются.** Игра переиспользует шаблон ID для уникальных
предметов верхнего тира: `T8_2H_AXE` — это не «Большой топор T8», а **«Рука
Кхора»** с другими способностями. Поэтому эквивалентом считается только вариант с
**тем же названием**; в каталоге таких ловушек 8 (`2H_AXE`, `2H_FIRESTAFF`,
`OFF_BOOK`, `2H_QUARTERSTAFF` и другие), и все они отсекаются.

Сканируется вся боевая экипировка **T4–T8** (оружие, оффхенды, броня, плащи,
сумки) — именно её покупает ЧР. Собирательская экипировка и инструменты
исключены: у них нулевой спрос на ЧР, проверено по API.

## Математика

Каноничный флип мгновенный с обеих сторон: выкупаешь существующий ордер продажи
в городе и жмёшь «Sell» в существующий ордер выкупа ЧР. **Ни одна нога не создаёт
рыночный ордер, поэтому сбора за размещение 2.5% нет** — только налог с продажи
(4% с Premium):

```
затраты  = цена продажи в городе
выручка  = ставка ЧР × 0.96
прибыль  = выручка − затраты
```

Если ты вместо этого ставишь **свой** ордер (buy order в городе или sell order на
ЧР), сбор появляется — в интерфейсе есть переключатель («⚙ Модель»), он честно
пересчитывает `net` в 0.935.

**Ключевая механика — лестница качества.** Ордер покупки принимает предметы
своего качества **и выше**, а ЧР считает каждое качество отдельным товаром и
часто платит за низкое качество больше, чем за высокое. Поэтому достижимая
ставка для предмета качества Q — это `max(ставка[q] для q ≤ Q)`, и в таблице
видно, в ордер какого качества продавать (значок `→ продать как «Хорошее»`).

Качества в игре, от низкого к высокому: Обычное, Хорошее, Незаурядное,
Отличное, Шедевральное. В таблице качество показано и цветной точкой у названия,
и словом. На реальных данных
**больше половины лучших флипов** продаются именно в ордер более низкого качества.

**Риск транспортировки.** Ганк отнимает весь груз, а не маржу:

```
ожидаемая ценность = (1 − p) × выручка − затраты
безубыточный p     = 1 − затраты / выручка
```

`p` — шанс ганка на рейс (ползунок, по умолчанию 8%; сообщества дают 5–15% в
прайм-тайм). Для закупки в самом Карлеоне `p = 0`.

**Надёжность 0–100** — свежесть цен (30%), ликвидность ЧР по логарифмической
шкале (22%), совпадение текущей ставки с историей (25%), живая глубина стакана
(13%), конкуренция чужих sell-ордеров на ЧР (10%). Ставка сильно выше средней
помечается как «скачок»: она обычно исчезает, пока ты едешь.

Полный разбор формул, источников данных и игровых механик — в
[`docs/HANDOFF.md`](docs/HANDOFF.md).

## Запуск на Ubuntu 24.04 (VPS)

```bash
curl -fsSL https://get.docker.com | sudo sh          # если Docker ещё не стоит
git clone https://github.com/mistermausee-cmd/shopalbi.git && cd shopalbi
sudo docker compose up -d --build
```

Открой `http://АДРЕС_VPS:8000` (в Azure не забудь открыть порт 8000 в NSG).

Первые ~20 секунд подтягиваются цены, ещё ~40 — история за 31 день. Индикатор
вверху станет зелёным. Дальше цены обновляются каждые 10 минут, история — каждые
6 часов, живой стакан течёт непрерывно.

**Обновление:**

```bash
cd ~/shopalbi && git fetch --all && git checkout -B main origin/main && sudo docker compose up -d --build
```

`Ctrl+F5` больше не нужен: `index.html` отдаётся с `no-cache`, а `app.js` и
`styles.css` запрашиваются с `?v=<версия>`.

**Логи:** `sudo docker compose logs -f` или файл на хосте
`/root/logs/shopalbi.log` (ротация 5 МБ × 3).

### Требования к серверу

Минимум — **1 vCPU / 1 ГБ RAM**: вся агрегация выполняется внутри SQLite,
поэтому память не зависит от объёма истории. Для такой машины поставь
`SHOPALBI_HISTORY_DAYS=31` и `SHOPALBI_SQLITE_CACHE_MB=64`.

Дефолты в `docker-compose.yml` рассчитаны на **4 vCPU / 16 ГБ**: 90 дней
истории, кеш SQLite 1 ГБ, обновление цен каждые 5 минут. Замерено на живых
данных:

| | значение |
|---|---|
| рефреш цен | 40 запросов, ~16 с |
| рефреш истории (90 дней) | 40 запросов, ~110 с, 3.35 млн бакетов |
| нагрузка на API | **8.2 зап/мин из лимита 180** (4.5%) |
| размер БД | ~540 МБ |
| `/api/flips`, `/api/plan` | 0.13–0.19 с |

Узкое место — не CPU и не RAM, а разреженность самих краудсорсных данных:
AODP обновляется только тогда, когда игроки открывают рынки в игре.

## Запуск без Docker

Нужен **Python 3.10+** (на 3.9 FastAPI не переварит аннотации `int | None`).

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## Настройка

Все параметры — переменные окружения, полный список с пояснениями в
[`.env.example`](.env.example). Чаще всего нужны:

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `SHOPALBI_SALES_TAX` | Налог продажи (Premium 0.04, без — 0.08) | `0.04` |
| `SHOPALBI_GANK_RATE` | Шанс потерять груз по дороге | `0.08` |
| `SHOPALBI_MIN_PROFIT` | Мин. прибыль для показа флипа | `1000` |
| `SHOPALBI_BM_MAX_AGE_HOURS` | Насколько старую ставку ЧР ещё считать живой | `3` |
| `SHOPALBI_ORDER_MAX_AGE_MINUTES` | Срок жизни живого ордера в стакане | `360` |
| `SHOPALBI_API_HOST` | Регион сервера | EU |
| `SHOPALBI_AUTH_USER` / `_PASS` | Пароль на сайт | пусто (открыт) |

## Проверка расчётов и выгрузка данных

**Самопроверка.** Пересчитывает все ключевые цифры заново — прямо из таблиц,
не через движок — и сравнивает с тем, что показывает интерфейс. Печатает
`MISMATCH`, если что-то расходится, а не соглашается сама с собой:

```bash
cd ~/shopalbi && sudo docker compose exec shopalbi python /app/scripts/audit.py --window week --top 10
```

Путь абсолютный не случайно: рабочая папка внутри контейнера — `/app/backend`,
а скрипты лежат в `/app/scripts`.

Показывает: состав окон и сверку VWAP вручную, лестницу качества с возрастом
каждой ставки, полный вывод прибыли по топовым флипам (затраты → налог →
прибыль → поправка на риск), разбор надёжности по слагаемым и сходимость сумм
в плане закупки.

**Выгрузка снимка БД.** Полная база с 90 днями истории весит ~540 МБ и в GitHub
не влезет (лимит 100 МБ на файл). Скрипт делает компактный снимок (~16 МБ в
архиве), сохраняя то, что нельзя восстановить позже — накопленный живой стакан,
котировки на момент снимка и свёрнутую историю:

```bash
cd ~/shopalbi && sudo docker compose exec shopalbi python /app/scripts/export_snapshot.py --out /logs
```

Файл появится в `/root/logs/shopalbi-snapshot-<дата>.db.gz`. Копия снимается
через штатный механизм SQLite, поэтому останавливать анализатор не нужно.
Обычным `cp` живую базу копировать нельзя — она в режиме WAL.

## Оговорки

- Данные краудсорсные: в них попадают только те рынки, которые игроки открывали в
  игре. Редкие предметы бывают с устаревшими ценами — движок помечает это низкой
  надёжностью и фильтрует по возрасту.
- «Выкупят за» — оценка по историческому обороту, а не гарантия. Продажа в
  существующий ордер происходит мгновенно; оценка говорит о глубине спроса.
- Живая глубина есть только там, где кто-то недавно открывал рынок в игре. Где её
  нет, количество ограничивается сверху и помечается тегом `оценка`.
- Инструмент только читает публичные данные. Никакой автоматизации игрового
  клиента здесь нет и не будет.
