# shopalbi — анализатор Чёрного рынка Albion Online

Веб-инструмент для схемы **«купил в королевском городе → отвёз в Карлеон →
продал на Чёрный рынок»**. Сервер **Europe**, аккаунт с **Premium**.

Собирает цены со всех королевских городов и ЧР, считает средние цены и оборот за
день / 3 дня / неделю / месяц и выдаёт ранжированный список того, что реально
стоит везти — с прибылью в серебре и процентах, поправкой на риск ганка, оценкой
надёжности и **реальным количеством, которое физически есть на рынке**.

Игру запускать не нужно. Данные — публичный
[Albion Online Data Project](https://www.albion-online-data.com): REST для цен и
истории плюс живой NATS-поток рыночных ордеров (цена **и количество**).

## Вкладки

| Вкладка | Что даёт |
|---|---|
| 🔥 **Выгодные флипы** | Топ вещей на вывоз: где купить, за сколько выкупит ЧР, прибыль, прибыль с учётом риска, при каком % ганков сделка выходит в ноль, доступное количество, надёжность. |
| 🧮 **План закупки** | Вписываешь бюджет — получаешь город, список вещей и **сколько штук брать**. Количества ограничены реальными ордерами (и предложением города, и спросом ЧР), поэтому «купи 300 шт T4» больше не бывает. |
| 🏙 **Города закупки** | Где выгоднее базироваться по совокупности факторов. Карлеон учитывается отдельно: цены выше, но риск потерять груз нулевой. |
| 📊 **Средние цены** | Средневзвешенные по объёму цены и оборот по всем городам за период, самый дешёвый город, исторический спред к ЧР. |

Сканируется вся боевая экипировка **T4–T8** (оружие, оффхенды, броня, плащи,
сумки) — именно её покупает ЧР. Собирательская экипировка и инструменты
исключены: у них нулевой спрос на ЧР, проверено по API.

## Математика

Каноничный флип мгновенный с обеих сторон: выкупаешь существующий ордер продажи
в городе и жмёшь «Sell» в существующий ордер выкупа ЧР. **Ни одна нога не создаёт
рыночный ордер, поэтому сбора за размещение 2.5% нет** — только налог с продажи
(4% с Premium):

```
затраты  = цена продажи в городе
выручка  = ставка ЧР × 0.96
прибыль  = выручка − затраты
```

Если ты вместо этого ставишь **свой** ордер (buy order в городе или sell order на
ЧР), сбор появляется — в интерфейсе есть переключатель («⚙ Модель»), он честно
пересчитывает `net` в 0.935.

**Ключевая механика — лестница качества.** Ордер покупки принимает предметы
своего качества **и выше**, а ЧР считает каждое качество отдельным товаром и
часто платит за низкое качество больше, чем за высокое. Поэтому достижимая
ставка для предмета качества Q — это `max(ставка[q] для q ≤ Q)`, и в таблице
видно, в ордер какого качества продавать (значок `→ qN`). На реальных данных
**больше половины лучших флипов** продаются именно в ордер более низкого качества.

**Риск транспортировки.** Ганк отнимает весь груз, а не маржу:

```
ожидаемая ценность = (1 − p) × выручка − затраты
безубыточный p     = 1 − затраты / выручка
```

`p` — шанс ганка на рейс (ползунок, по умолчанию 8%; сообщества дают 5–15% в
прайм-тайм). Для закупки в самом Карлеоне `p = 0`.

**Надёжность 0–100** — свежесть цен (30%), ликвидность ЧР по логарифмической
шкале (22%), совпадение текущей ставки с историей (25%), живая глубина стакана
(13%), конкуренция чужих sell-ордеров на ЧР (10%). Ставка сильно выше средней
помечается как «скачок»: она обычно исчезает, пока ты едешь.

Полный разбор формул, источников данных и игровых механик — в
[`docs/HANDOFF.md`](docs/HANDOFF.md).

## Запуск на Ubuntu 24.04 (VPS)

```bash
curl -fsSL https://get.docker.com | sudo sh          # если Docker ещё не стоит
git clone https://github.com/mistermausee-cmd/shopalbi.git && cd shopalbi
sudo docker compose up -d --build
```

Открой `http://АДРЕС_VPS:8000` (в Azure не забудь открыть порт 8000 в NSG).

Первые ~20 секунд подтягиваются цены, ещё ~40 — история за 31 день. Индикатор
вверху станет зелёным. Дальше цены обновляются каждые 10 минут, история — каждые
6 часов, живой стакан течёт непрерывно.

**Обновление:**

```bash
cd ~/shopalbi && git fetch --all && git checkout -B main origin/main && sudo docker compose up -d --build
```

`Ctrl+F5` больше не нужен: `index.html` отдаётся с `no-cache`, а `app.js` и
`styles.css` запрашиваются с `?v=<версия>`.

**Логи:** `sudo docker compose logs -f` или файл на хосте
`/root/logs/shopalbi.log` (ротация 5 МБ × 3).

### Требования к серверу

**1 vCPU / 1 ГБ RAM** (Azure B1s), ~1.5 ГБ диска. Вся агрегация выполняется
внутри SQLite, поэтому память не зависит от объёма истории.

## Запуск без Docker

Нужен **Python 3.10+** (на 3.9 FastAPI не переварит аннотации `int | None`).

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## Настройка

Все параметры — переменные окружения, полный список с пояснениями в
[`.env.example`](.env.example). Чаще всего нужны:

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `SHOPALBI_SALES_TAX` | Налог продажи (Premium 0.04, без — 0.08) | `0.04` |
| `SHOPALBI_GANK_RATE` | Шанс потерять груз по дороге | `0.08` |
| `SHOPALBI_MIN_PROFIT` | Мин. прибыль для показа флипа | `1000` |
| `SHOPALBI_BM_MAX_AGE_HOURS` | Насколько старую ставку ЧР ещё считать живой | `3` |
| `SHOPALBI_ORDER_MAX_AGE_MINUTES` | Срок жизни живого ордера в стакане | `360` |
| `SHOPALBI_API_HOST` | Регион сервера | EU |
| `SHOPALBI_AUTH_USER` / `_PASS` | Пароль на сайт | пусто (открыт) |

## API

`/api/status`, `/api/meta`, `/api/flips`, `/api/plan`, `/api/cities`,
`/api/stats`, `/api/refresh`, `/api/health`. Все таблицы выгружаются в CSV
кнопкой в интерфейсе.

## Оговорки

- Данные краудсорсные: в них попадают только те рынки, которые игроки открывали в
  игре. Редкие предметы бывают с устаревшими ценами — движок помечает это низкой
  надёжностью и фильтрует по возрасту.
- «Выкупят за» — оценка по историческому обороту, а не гарантия. Продажа в
  существующий ордер происходит мгновенно; оценка говорит о глубине спроса.
- Живая глубина есть только там, где кто-то недавно открывал рынок в игре. Где её
  нет, количество ограничивается сверху и помечается тегом `оценка`.
- Инструмент только читает публичные данные. Никакой автоматизации игрового
  клиента здесь нет и не будет.
